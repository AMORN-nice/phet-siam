# เอกสารออกแบบ: Splendor ธีมสยามโบราณ เล่นออนไลน์กับเพื่อน

วันที่: 2026-11-17

## 1. เจตนาและเหตุผล
ผู้ใช้อยากเล่นเกมแนว Splendor กับกลุ่มเพื่อนแบบออนไลน์เรียลไทม์ ระหว่างคุยกันใน Discord ทุกคนเปิดเกมจากเครื่องตัวเองและเห็นกระดานเดียวกันพร้อมกัน ระบบตรวจกติกา บังคับลำดับตา และนับแต้มให้ ภาพทั้งหมดทำใหม่ด้วย PixelLab ในธีมสยามโบราณ และ UI เป็นภาษาไทย

## 2. เป้าหมาย / ไม่ใช่เป้าหมาย / สิ่งที่ถือว่าล้มเหลว
**เป้าหมาย**
- เล่นได้ 2–5 คน แบบเรียลไทม์ ผ่านลิงก์เว็บ ไม่ต้องสมัครบัญชี
- ระบบห้องที่มีรหัสห้องสำหรับส่งให้เพื่อนใน Discord
- กติกาครบตามเกมต้นฉบับ และปรับจำนวนของตามจำนวนผู้เล่น
- ภาพการ์ด ขุนนาง อัญมณี และ UI เป็น pixel art ธีมสยามโบราณจาก PixelLab

**ไม่ใช่เป้าหมาย (ไม่ทำ)**
- AI หรือบอทเล่นแทนคน
- ระบบบัญชี อันดับ หรือสถิติระยะยาว
- แชทในเกม เพราะคุยกันใน Discord อยู่แล้ว
- แอปมือถือ (แต่หน้าเว็บควรใช้บนจอเล็กได้พอสมควร)
- ภาคเสริม (Cities, Orient ฯลฯ)

**ถือว่าล้มเหลวแม้โค้ดจะทำงาน**
- สถานะเกมของแต่ละคนไม่ตรงกัน หรือเกิดการโกงด้วยการแก้โค้ดฝั่งเบราว์เซอร์ได้
- คนที่หลุดกลางเกมกลับเข้ามาไม่ได้ ทำให้เกมทั้งโต๊ะพัง
- ใช้ชื่อ "Splendor" ภาพ หรือโลโก้ของต้นฉบับ

## 3. กติกา
ใช้กติกา Splendor ต้นฉบับครบถ้วน:
- ในตาตัวเองทำได้ 1 อย่าง:
  1. หยิบอัญมณีต่างสีกัน 3 เม็ด (ถ้ามีสีที่เหลือในกองไม่ถึง 3 สี ให้หยิบเท่าที่มี)
  2. หยิบอัญมณีสีเดียวกัน 2 เม็ด (กองสีนั้นต้องมีอย่างน้อย 4 เม็ดก่อนหยิบ)
  3. จองการ์ด 1 ใบจากที่เปิดอยู่หรือจากกองคว่ำ และได้ทอง 1 เม็ดถ้ายังมีเหลือ (จองได้สูงสุด 3 ใบ)
  4. ซื้อการ์ดที่เปิดอยู่หรือการ์ดที่จองไว้ โดยหักส่วนลดจากโบนัสการ์ดที่มีอยู่ ใช้ทองแทนสีอะไรก็ได้
- ถืออัญมณีรวมทองได้ไม่เกิน 10 เม็ด ถ้าเกินต้องทิ้งคืนกองจนเหลือ 10
- ตอนจบตา ถ้ามีขุนนางที่เงื่อนไขครบ ขุนนางจะมาหาเอง 1 คน ถ้าครบหลายคน ผู้เล่นเลือกเอง
- เมื่อมีผู้เล่นถึง 15 แต้ม ให้เล่นต่อจนครบรอบ (จนถึงคนก่อนผู้เล่นคนแรก) แล้วคนที่มีแต้มมากสุดชนะ ถ้าเสมอกัน คนที่มีการ์ดพัฒนาน้อยกว่าชนะ
- ข้อมูลการ์ด 90 ใบและขุนนาง 10 ใบ (ราคา แต้ม โบนัส) ใช้ชุดเดียวกับต้นฉบับ เพราะเป็นกลไกของเกม แต่ตั้งชื่อและวาดภาพใหม่ทั้งหมด

**ของตามจำนวนผู้เล่น**

| ผู้เล่น | อัญมณีต่อสี | ขุนนาง | ทอง |
|---|---|---|---|
| 2 | 4 | 3 | 5 |
| 3 | 5 | 4 | 5 |
| 4 | 7 | 5 | 5 |
| 5 | 7 | 6 | 5 |

แถว 5 คนเป็น house rule ที่ผู้ใช้อนุมัติแล้ว (ต้นฉบับไม่มีกติกา 5 คน)

## 4. ข้อจำกัด
- Claude deploy ขึ้นอินเทอร์เน็ตจาก workspace ไม่ได้ ผู้ใช้จึงต้อง deploy เอง เอกสารจึงต้องมีขั้นตอน deploy ทีละข้อที่คนไม่ใช่โปรแกรมเมอร์ทำตามได้
- โฮสต์ฟรี (Render) จะหลับเมื่อไม่มีคนใช้ เปิดครั้งแรกเลยช้า 30–60 วินาที ซึ่งยอมรับได้
- asset ทั้งหมดต้องมาจาก PixelLab ผ่านเครื่องของผู้ใช้ และต้องคุมจำนวนการเจนไม่ให้เปลืองเครดิตเกินจำเป็น

## 7. สถาปัตยกรรม (การตัดสินใจของ Claude)
- **เซิร์ฟเวอร์:** Node.js + Express + Socket.io รันเป็น process เดียว ทำหน้าที่ทั้งเสิร์ฟไฟล์หน้าเว็บและ asset และเป็นผู้ตัดสินกติกาแต่เพียงผู้เดียว ไคลเอนต์ส่งมาแค่ "คำสั่ง" (เช่น หยิบ/จอง/ซื้อ) เซิร์ฟเวอร์ตรวจแล้วส่งสถานะเต็มกลับไปให้ทุกคนในห้อง
- **โค้ดกติกา:** เป็นโมดูลแยก (pure functions: `state + action → state | error`) มี unit test ครอบคลุม
- **ข้อมูลที่ต้องซ่อน:** เซิร์ฟเวอร์ไม่ส่งสถานะดิบให้ทุกคน แต่ส่ง "มุมมองเฉพาะคน" ลำดับการ์ดในกองคว่ำจะไม่ถูกส่งไปเลย ส่วนการ์ดที่คนอื่นจองจากกองคว่ำ เราจะเห็นแค่ระดับของการ์ด แต่การ์ดที่เขาจองจากแถวที่เปิดอยู่ ทุกคนเห็นได้ตามกติกาเดิม *(การตัดสินใจของ Claude)*
- **ไคลเอนต์:** HTML/CSS/JS ล้วน ไม่มีขั้นตอน build แสดงผลด้วย DOM และใช้ `image-rendering: pixelated`
- **ห้อง:** รหัส 4 ตัวอักษร คนสร้างห้องเป็นหัวห้อง ใส่ชื่อเล่นก่อนเข้าห้อง หัวห้องกดเริ่มเกมได้เมื่อมีผู้เล่น 2–5 คน ลำดับผู้เล่นสุ่ม
- **กลับเข้าเกม:** แต่ละคนได้ token เก็บไว้ใน localStorage ถ้าหลุดแล้วเปิดลิงก์ห้องใหม่ จะกลับเข้าที่นั่งเดิมได้ ระหว่างที่ใครหลุด เกมรอคนนั้น (ไม่ข้ามตา) และหัวห้องมีปุ่ม "ข้ามตาคนที่หลุด"
- **หัวห้องหลุด:** สิทธิ์หัวห้องจะย้ายไปที่ผู้เล่นคนถัดไปที่ยังออนไลน์อยู่ *(การตัดสินใจของ Claude)*
- **ล้าง localStorage หรือเปลี่ยนเครื่อง:** ถ้าเกมเริ่มแล้ว ให้เลือก "เข้าแทนที่นั่ง" ของคนที่กำลังหลุดอยู่ได้ เกมที่เริ่มแล้วจะรับคนใหม่หรือผู้ชมไม่ได้ *(การตัดสินใจของ Claude)*
- **ทิ้งอัญมณีที่เกิน 10:** หลังทำ action แล้วถ้าถือเกิน 10 เม็ด จะมีหน้าต่างให้เลือกเม็ดที่จะทิ้ง และตาของคนนั้นจะยังไม่จบจนกว่าจะทิ้งเสร็จ *(การตัดสินใจของ Claude)*
- **เสมอทั้งแต้มและจำนวนการ์ด:** ถือว่าชนะร่วมกัน *(การตัดสินใจของ Claude)*
- **เก็บสถานะ:** เก็บไว้ในหน่วยความจำ ถ้าเซิร์ฟเวอร์รีสตาร์ท เกมที่ค้างอยู่จะหายไป ซึ่งยอมรับได้สำหรับการเล่นกับเพื่อน ห้องที่ไม่มีใครอยู่เกิน 30 นาทีจะถูกลบ (Render ฟรีจะหลับหลังว่างราว 15 นาที ซึ่งก็ล้างห้องไปด้วย เกมที่กำลังเล่นอยู่จึงไม่โดนผลกระทบ)
- **Deploy:** ใช้ Render แพ็กเกจฟรี พร้อมคู่มือภาษาไทยทีละขั้น (GitHub → Render) และรันในเครื่องได้ด้วย `npm start`

## 8. หน้าจอ
1. **หน้าแรก:** ช่องใส่ชื่อเล่น ปุ่ม "สร้างห้อง" และช่องใส่รหัสห้องพร้อมปุ่ม "เข้าห้อง"
2. **ห้องรอ:** แสดงรหัสห้อง ปุ่มคัดลอกลิงก์ รายชื่อผู้เล่น และปุ่ม "เริ่มเกม" (เห็นเฉพาะหัวห้อง)
3. **กระดานเกม:**
   ```
   [ขุนนาง x N                                          ]
   [กองคว่ำ ร.3] [การ์ด] [การ์ด] [การ์ด] [การ์ด]   [ อัญมณี ]
   [กองคว่ำ ร.2] [การ์ด] [การ์ด] [การ์ด] [การ์ด]   [ 5 สี  ]
   [กองคว่ำ ร.1] [การ์ด] [การ์ด] [การ์ด] [การ์ด]   [ + ทอง ]
   [แผงผู้เล่นคนอื่น: ชื่อ แต้ม อัญมณี โบนัส จำนวนการ์ดจอง]
   [แผงของเรา: อัญมณี โบนัส การ์ดที่จอง ปุ่มยืนยัน/ยกเลิก]
   ```
   ไฮไลต์ว่าตาใคร และมีบันทึกการเดินสั้นๆ บอกว่าใครทำอะไร
4. **หน้าจบเกม:** ตารางแต้ม ประกาศผู้ชนะ และปุ่ม "เล่นอีกครั้ง" (ห้องเดิม คนเดิม)

## 9. Asset จาก PixelLab (ธีมสยามโบราณ)
ไม่วาดการ์ด 90 ใบไม่ซ้ำกัน แต่ใช้ **ภาพประกอบ 1 ภาพต่อระดับต่อสี = 15 ภาพ** แล้วให้โค้ดซ้อนแต้ม ราคา และสัญลักษณ์โบนัสลงบนภาพ

| หมวด | จำนวน | รายละเอียด |
|---|---|---|
| ภาพการ์ด ระดับ 1 | 5 | แผงตลาด เหมืองพลอย ช่างฝีมือ (1 ภาพต่อสี) |
| ภาพการ์ด ระดับ 2 | 5 | เรือสำเภา ตลาดน้ำ โรงทอผ้าไหม ฯลฯ |
| ภาพการ์ด ระดับ 3 | 5 | วัด พระราชวัง ช้างทรง ฯลฯ |
| หลังการ์ด | 3 | ระดับละ 1 แบบ |
| ขุนนาง | 10 | ภาพเหมือนขุนนางและเจ้านายในชุดไทยโบราณ |
| อัญมณี | 6 | 5 สี (ขาว น้ำเงิน เขียว แดง ดำ) + ทอง เป็นเหรียญ/พลอยสไตล์สยาม |
| ไอคอนโบนัส | 5 | ไอคอนเล็กสำหรับมุมการ์ด (อาจครอปจากภาพอัญมณี) |
| พื้นหลังโต๊ะ | 1 | ลายผ้าหรือไม้แกะสลัก ปูซ้ำได้ |
| กรอบ UI / ปุ่ม | 2–4 | กรอบแผงลายไทย และปุ่ม |
| เสียง (ถ้าเครดิตพอ) | 3–4 | หยิบเหรียญ ซื้อการ์ด ขุนนางมาเยือน จบเกม |

**งบและผู้สั่งเจน (ผู้ใช้อนุมัติแล้ว):** Claude สั่งเจนเองผ่านเครื่องของผู้ใช้ ใช้ไม่เกิน 300 generations ระหว่างที่ภาพยังไม่เสร็จ เกมต้องเล่นได้ด้วยภาพชั่วคราวที่วาดด้วยโค้ด

ตั้ง palette และสไตล์อ้างอิงร่วมกันตั้งแต่ภาพแรก เพื่อให้ทุกภาพเข้าชุดกัน และตรวจเครดิต PixelLab ก่อนเจนจำนวนมาก ถ้าการเจนลายไทยออกมาไม่สวยในรอบแรก ให้ลดรายละเอียดลาย แล้วเน้นรูปทรงและสีแทน

## 10. สิ่งที่เปิดให้ผู้สร้างตัดสินใจ
- ขนาดพิกเซลของแต่ละ asset และการจัด layout ที่ responsive
- ชื่อไทยของการ์ดแต่ละระดับและขุนนาง
- รูปแบบ animation ย่อย (เช่น เหรียญลอยไปหาผู้เล่น)
- โครงสร้างโฟลเดอร์ของโปรเจกต์
- ชื่อเกม (ห้ามใช้ "Splendor") โดย Claude จะเสนอชื่อไทยให้
